Support

Start with the Getting Started guide, then use the public issue tracker for reproducible product defects, documentation problems, and feature requests.

Keep operational data private. Do not upload employer event logs, report files, screenshots with case identifiers, tenant details, credentials, or proprietary field names. Build a synthetic reproduction instead.

Before opening an issue

  1. Confirm Case ID, Activity, and Timestamp are mapped to the intended columns.
  2. Check that timestamps have a consistent data type and valid values.
  3. Press Analyze or Reanalyze after changing the mapped data or filters.
  4. Try the same steps in a blank report with a small synthetic dataset.
  5. Review the known issues and product limits.

Include in a bug report

  • Threadseer version.
  • Power BI Desktop, Service, or embedded environment and its version.
  • Exact reproduction steps using synthetic field names and data.
  • Expected and actual result.
  • Whether the problem also occurs in a blank report.

Security reports

Use private vulnerability reporting. Do not disclose a suspected vulnerability publicly.

Support is provided on a reasonable-efforts basis. No response or resolution time is guaranteed unless a separate written agreement says otherwise.
